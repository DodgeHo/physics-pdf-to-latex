# 批量成卷规范（几十卷一次做完）

一次接手多卷时，本文件是硬约束。与 workflow.md 的差别只在"隔离、并行、验收"三件事。

## 1. 卷清单先落地

先写一份批次清单：卷名（规范名）、源文件绝对路径、页数、是否纯扫描、是否自带答案键。**卷名一次定死**，后续所有路径、题号标记、问题记录都用它，不再改名（如 `2026安徽` 不写成 `2026-Anhui`）。

- 源为 docx 的，先批量转 PDF：Word COM `$doc.SaveAs2($out, 17)`，产物放 `_converted/`；一个 docx 对应一卷，题干与答案分两个文件的（如 paper + solutions）合为一卷。
- 纯扫描件（文字层近乎为空）在清单里标出来，走 3.6x 路径，单独派任务。

## 2. 目录隔离

```
<root>/
├── tex输出/<卷名>/<卷名>.tex + images/
├── tex输出/_notes/<卷名>.md
├── _tmp/<卷名>/            # 该卷裁图与总览，只在写这一卷时用
└── 汇总说明.md              # 全部完成后统一写
```

- 一卷只由一个人写：两个子任务共用一卷目录必然互相覆盖。
- 已交付的卷目录**只读**：任何子任务不得改写、覆盖、删除。
- 源 PDF/DOCX、`_tools/`、`_converted/` 一律只读。

## 3. 拆组派工

- 按实际页数均衡：一般 4–6 卷/组；纯扫描卷与 20 页以上超长卷单独成组。
- 每组下发：卷名清单、源路径、模板卷路径（挑两卷已交付的成稿做格式基线）、答案口径、问题记录格式。
- 每组回执必带逐卷行：`卷名 | 题数 | 配图数 | verify(OK/FAIL) | 问题条数 | 主要问题一句话`。FAIL 不得报成完成。

## 4. 答案口径（批量时最容易走样，逐字执行）

1. 答案 = 源答案键，不用自己的结果替换。
2. 源无答案 → 独立推导，问题记录写"需人工复核"。
3. 题干缺 → 可用公开真题补齐题面与配图，问题记录写明来源；**答案与解析不照抄网络**，网络答案只用于比对，差异双向登记（"公开答案记 X，独立推导为 Y"）。
4. 数字、指数、系数辨认不清 → 以渲染图为准；仍不清的写进问题记录，别猜。
5. 缺题、缺选项、缺小问 → 如实登记，跳号不占位。

## 5. 收尾验收（缺一项不算完成）

1. 全量逐卷跑 `verify_tex.py`，全部 `OK` 且 `missing=[]`。
2. 比对 `共 N 题` 与实际 `^\noindent \d+\.` 条数一致；`答案：`/`解析：` 行数 ≥ 题数。
3. `images/` 里没有未被引用的裁图副本；`refs` 数与引用数一致。
4. 每卷 `_notes/<卷名>.md` 存在，五栏齐全，问题栏非空。
5. 汇总 `_notes/_SUMMARY.md`：全卷总表（卷名/题数/配图/校验/问题条数）+ 分类清单（题面非本地源、缺题跳号、答案键冲突、扫描 OCR 风险）。

## 6. 派工纪律

- 子任务 `subtask` 必须写明"只做这几卷"，否则会误按全量执行并覆盖别人的活。
- 并发上限按框架给（常见 5），空位再补派，不要一次性压满。
- 子任务完成后主控要独立复核（重跑 verify + 抽查问题记录），不采信自述。
